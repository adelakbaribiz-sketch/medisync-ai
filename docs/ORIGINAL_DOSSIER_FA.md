# شرح فنی پلتفرم تداخلات دارویی مبتنی بر هوش مصنوعی

## ۱. نام پیشنهادی پلتفرم

**MediSync AI** — ترکیبی از "Medication" و "Synergy"، که هم‌زمان مفهوم هم‌افزایی دارویی و هم‌اهنگی در تصمیم‌گیری بالینی را منتقل می‌کند.

نام‌های جایگزین:
- **PharmaGuard AI** — تأکید بر حفاظت و ایمنی دارویی
- **InteractIQ** — ترکیب Interaction و IQ
- **DrugSense** — حس دارویی هوشمند
- **RxBridge** — پل ارتباطی بین داروها

نام **MediSync AI** برای ارائه بین‌المللی مناسب‌تر است زیرا در زبان‌های مختلف قابل تلفظ بوده و مفهوم "هم‌اهنگی دارویی هوشمند" را به‌خوبی منتقل می‌کند.


## ۲. تحلیل رقبا و شکاف‌های موجود

### ۲.۱. رقبای اصلی

| پلتفرم | نقاط قوت | نقاط ضعف کلیدی |
|---|---|---|
| **DrugBank** | پایگاه داده جامع، API برای محققان، پوشش تداخلات دارو-غذا و بیولوژیک | داده‌های خام بدون تحلیل هوشمند، رابط کاربری قدیمی |
| **Lexi-Interact (UpToDate)** | معتبرترین منبع بالینی | قیمت بسیار بالا، عدم یکپارچگی آسان |
| **Micromedex** | پشتیبانی از بیمارستان‌ها | پیچیدگی بالا، عدم پشتیبانی از مدل‌های زبانی |
| **Medscape** | رایگان، محبوب در میان پزشکان | عدم شفافیت در سطوح شواهد |
| **Epocrates** | اپ موبایل رایگان | نسخه پرمیوم محدود، پوشش گیاهی-دارویی ضعیف |

### ۲.۲. شکاف‌های کلیدی رقبا

**شکاف ۱ — عدم توافق بین منابع:** مطالعات نشان می‌دهد توافق کلی بین پنج ابزار تداخل‌سنجی مختلف بسیار پایین است (Gwet AC1: ۰.۱۶ تا ۰.۲۴). حتی بین Lexi-Interact و Drugs.com توافق منفی (تصادفی یا اختلاف قابل‌توجه) مشاهده شده است.

**شکاف ۲ — دقت پایین مدل‌های زبانی موجود:** ارزیابی پلتفرم‌های AI (ChatGPT, Gemini, Copilot) برای غربالگری تداخلات نشان می‌دهد بالاترین F1 Score فقط ۰.۲۵۲۰ (ChatGPT) بوده و همه پلتفرم‌ها دقت پایینی دارند.

**شکاف ۳ — عدم شفافیت شواهد:** بیشتر ابزارهای تجاری درباره منابع شواهد خود مبهم هستند و مکانیسم عمل تداخل را توضیح نمی‌دهند.

**شکاف ۴ — عدم یکپارچگی استاندارد:** اکثر پلتفرم‌ها از استانداردهای FHIR و CDS Hooks پشتیبانی نمی‌کنند.

**شکاف ۵ — نبود چندعاملی هوشمند:** سیستم‌های موجود مبتنی بر قوانین ایستا هستند و فاقد قابلیت استدلال چندمرحله‌ای و انطباق با بیمار خاص هستند.

## ۴. طراحی ظاهری (Frontend / UI/UX)

### ۴.۱. اصول طراحی

بر اساس بهترین شیوه‌های UX برای سیستم‌های پشتیبانی تصمیم دارویی، اصول زیر رعایت می‌شود:

- **نمای کلی در یک نگاه:** نمایش تمام تداخلات بالقوه در صفحه اصلی، بدون نیاز به ناوبری عمیق
- **تمایز بصری واضح:** هشدارها با رنگ‌بندی مشخص از سایر بخش‌های صفحه متمایز شوند (Contraindicated: قرمز، Major: نارنجی، Moderate: زرد، Minor: آبی)
- **شفافیت شواهد:** هر هشدار شامل لینک به منبع اصلی (FDA Label، PubMed، DrugBank) باشد
- **دسترس‌پذیری:** پشتیبانی از هشدارهای صوتی و کنتراست بالا

### ۴.۲. ساختار صفحات

**صفحه اصلی (Dashboard):**
- جستجوی دارو با AutoComplete (پشتیبانی از RxNorm RxCUI، نام ژنریک و برند)
- لیست داروهای وارد شده با قابلیت drag & drop
- نمایش گرافیکی شبکه تداخلات (Knowledge Graph Visualization)
- خلاصه ریسک: تعداد تداخلات بر اساس سطح شدت

**صفحه تحلیل تداخل:**
- جدول تداخلات با ستون‌های: دارو ۱، دارو ۲، شدت، مکانیسم، شواهد، توصیه بالینی
- نمایش مکانیسم عمل (CYP450 inhibition، P-glycoprotein، additive effects)
- سطح شواهد (Study، Anecdotal، Theoretical، None)
- پیشنهاد داروهای جایگزین با تداخل کمتر

**صفحه پروفایل بیمار:**
- ورود اطلاعات بیمار: سن، وزن، eGFR، عملکرد کبدی، بارداری، آلرژی‌ها
- تعدیل خودکار هشدارها بر اساس وضعیت بیمار
- تاریخچه تداخلات قبلی

**صفحه مستندات و شواهد:**
- نمایش متون تأییدشده FDA/EMA با لینک DailyMed
- خلاصه مقالات PubMed مرتبط
- سطح قطعیت شواهد با سیستم GRADE

### ۵.۲. میکروسرویس‌ها

**۱. سرویس مدیریت دارو (Drug Service)**
- نرمال‌سازی نام دارو با RxNorm API (تبدیل نام تجاری به RxCUI)
- اعتبارسنجی و تطبیق داروها
- مدیریت کدهای NDC، ATC، SNOMED CT

**۲. موتور تداخل (Interaction Engine)**
- هسته اصلی پلتفرم
- ترکیب سه لایه: (الف) قوانین قطعی از پایگاه داده، (ب) مدل GNN برای پیش‌بینی تداخلات ناشناخته، (ج) LLM محلی برای استدلال و تولید توضیح
- خروجی ساختاریافته با JSON Schema

**۳. سرویس بازیابی شواهد (Evidence Retrieval)**
- RAG Pipeline: جستجوی ترکیبی (BM25 + pgvector cosine similarity)
- بازیابی از: FDA Labels (DailyMed)، PubMed Abstracts، DrugBank Text، EMA Documents
- تولید پاسخ با ارجاع به منبع اصلی

**۴. سرویس متن بیمار (Patient Context Service)**
- دریافت FHIR Patient Resource
- تعدیل هشدارها بر اساس: سن، eGFR، عملکرد کبدی، بارداری، پلی‌فارماسی
- محاسبه امتیاز خطر شخصی‌سازی‌شده

**۵. سرویس یکپارچگی (Integration Service)**
- پشتیبانی از **FHIR R4** و **CDS Hooks**
- پیاده‌سازی PDDI CDS Specification (HL7)
- Prefetch Template برای order-select و order-sign
- پشتیبانی از SMART on FHIR برای یکپارچگی با EHR

### ۵.۳. جریان داده

```
کاربر داروها را وارد می‌کند
        │
        ▼
[Drug Service] → نرمال‌سازی با RxNorm → دریافت RxCUI
        │
        ▼
[Interaction Engine] → جستجوی موازی:
        ├── پایگاه داده قطعی (PostgreSQL)
        ├── مدل GNN (ONNX Runtime)
        └── LLM محلی (Ollama)

[Evidence Retrieval] → RAG از FDA/PubMed/DrugBank
        │

        │
        ▼
خروجی ساختاریافته + سطح شواهد + توصیه بالینی
```


## ۶. موتور هوش مصنوعی (AI Engine)

### ۶.۱. معماری سه‌لایه

**لایه ۱ — پایگاه داده قطعی (Deterministic Layer):**
- تداخلات شناخته‌شده از DrugBank، FDA Labels، RxNorm API
- قوانین CYP450 و transporter-mediated DDI مطابق ICH M12
- خروجی: تداخلات قطعی با سطح شواهد

**لایه ۲ — مدل گراف عصبی (GNN Layer):**
- معماری: **Graph Attention Network (GAT)** برای پیش‌بینی تداخلات ناشناخته
- ورودی: ساختار مولکولی داروها + Knowledge Graph (DRKG)
- آموزش بر روی DDInter Dataset و DrugBank
- خروجی: امتیاز احتمالی تداخل + مکانیسم پیشنهادی
- مدل‌های پیشرفته: MFHNN-DDI (ACC و F1 بالای ۹۰٪ روی DDInter)

**لایه ۳ — مدل زبانی محلی (LLM Layer):**
- مدل: **Llama 3.1 8B** یا **Qwen 2.5 7B**، اجرا شده با **Ollama**
- Fine-tuning با **QLoRA** روی داده‌های تخصصی تداخلات دارویی
- خروجی محدود شده با **JSON Schema** برای جلوگیری از توهم
- استدلال چندمرحله‌ای برای بررسی تداخلات N-دارویی

### ۶.۲. استراتژی RAG

```
Query → Embedding (Biomedical Sentence-BERT)
        │
        ▼
Hybrid Search (BM25 + pgvector) روی PostgreSQL
        │
        ▼
Top-K Results → Re-ranking (Cross-Encoder)
        │
        ▼
Context + Query → LLM → پاسخ با ارجاع به منبع
```

- **مدل Embedding:** PubMedBERT یا BioLORD برای متن‌های پزشکی
- **Vector Store:** pgvector در PostgreSQL با HNSW Index
- **Hybrid Search:** ترکیب BM25 (کلیدواژه) + cosine similarity (معنایی)

### ۶.۳. سیستم چندعاملی (Multi-Agent)

بر اساس معماری‌های پیشرفته مانند MedFusion-Agent:

| عامل | وظیفه |
|---|---|
| **Orchestrator Agent** | مسیریابی درخواست، تجمیع نتایج |
| **Interaction Agent** | تحلیل تداخلات دارو-دارو |
| **Safety Agent** | بررسی نهایی ایمنی و کاهش ریسک |
| **Alternative Agent** | پیشنهاد داروهای جایگزین |
| **Explanation Agent** | تولید توضیح بالینی قابل فهم |
| **Evidence Agent** | جمع‌آوری و اعتبارسنجی شواهد |

تحقیقات نشان می‌دهد حضور Safety Agent نرخ تداخلات را به طور قابل‌توجهی کاهش می‌دهد (DDI Rate Mean: ۰.۰۸۰ با Safety Agent در مقابل ۰.۴۲ بدون آن).

## ۸. الزامات قانونی و انطباق

### ۸.۱. FDA (آمریکا)
- **CDS Software:** اگر پلتفرم فقط اطلاعات تداخل را نمایش دهد و توصیه درمانی مستقیم ارائه نکند، ممکن است به عنوان "Non-Device CDS" طبقه‌بندی شود
- **SaMD:** اگر توصیه‌های درمانی شخصی‌سازی‌شده ارائه دهد، ممکن است نیاز به تأیید 510(k) یا De Novo داشته باشد
- **PDURS:** مطابقت با راهنمای Prescription Drug Use-Related Software

### ۸.۲. EMA (اروپا)
- **ICH M12:** مطابقت با استانداردهای مطالعات تداخلات دارویی (FDA, EMA, PMDA)
- **CE Marking:** برای Class IIb Medical Device
- **GDPR:** رمزنگاری داده‌ها، ناشناس‌سازی، حق فراموش شدن

### ۸.۳. HIPAA (آمریکا)
- رمزنگاری داده‌های بیمار در حال انتقال و ذخیره‌سازی
- کنترل دسترسی مبتنی بر نقش (RBAC)
- لاگ حسابرسی کامل
- De-identification قبل از پردازش AI

### ۸.۴. استانداردهای فنی
- **HL7 FHIR R4:** برای تبادل داده‌های بالینی
- **CDS Hooks:** برای یکپارچگی با EHR
- **SNOMED CT / RxNorm / LOINC:** برای اصطلاحات پزشکی
- **CQL:** برای منطق قواعد بالینی

### ۹.۱. تمایزات کلیدی

**۱. دقت بالاتر:** ترکیب GNN + RAG + LLM محلی با خروجی محدود شده با JSON Schema، از توهم جلوگیری می‌کند و دقت را به طور قابل‌توجهی افزایش می‌دهد.

**۲. شفافیت کامل:** هر هشدار شامل لینک به منبع اصلی (DailyMed، PubMed ID) است — الزامی که بیشتر رقبا آن را رعایت نمی‌کنند.

**۳. حریم خصوصی مطلق:** پردازش کامل روی سرور محلی، بدون ارسال داده بیمار به ابر — مناسب برای بیمارستان‌ها و کلینیک‌های حساس به HIPAA/GDPR.

**۴. یکپارچگی استاندارد:** پشتیبانی بومی از FHIR R4 و CDS Hooks، که اجازه می‌دهد پلتفرم مستقیماً درون EHR (مانند Epic, Cerner) ادغام شود.

**۵. استدلال چندمرحله‌ای:** سیستم چندعاملی می‌تواند تداخلات N-دارویی پیچیده را تحلیل کند و داروهای جایگزین پیشنهاد دهد.

**۶. تعدیل بیمار-محور:** هشدارها بر اساس وضعیت فیزیولوژیک بیمار (عملکرد کلیوی، کبدی، سن) تعدیل می‌شوند — قابلیتی که در بیشتر رقبا وجود ندارد.

## نتیجه‌گیری

MediSync AI با ترکیب **GNN + RAG + LLM محلی** و معماری **چندعاملی**، از شکاف‌های کلیدی رقبا (دقت پایین، عدم شفافیت، عدم شخصی‌سازی، حریم خصوصی ضعیف) عبور می‌کند. استفاده از **FastAPI + PostgreSQL + pgvector** به عنوان بک‌اند و **Next.js + D3.js** به عنوان فرانت‌اند، پایه‌ای محکم و مقیاس‌پذیر فراهم می‌کند. پشتیبانی بومی از **FHIR R4 و CDS Hooks** امکان یکپارچگی با سیستم‌های EHR بیمارستانی را فراهم می‌سازد و اجرای کاملاً محلی، بالاترین سطح حریم خصوصی را تضمین می‌کند.
